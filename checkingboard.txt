CHECKINGBOARD PROJECT - MASTER CONTEXT & SPECIFICATION

This file serves as the living context and specification document for the
CheckingBoard dispatch application. Whenever any new feature or change is added,
it must be documented in this file.

--------------------------------------------------------------------------------
1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
CheckingBoard is a dynamic, Excel-inspired fleet dispatch tracker built for
dispatchers and fleet managers. It categorizes truck drivers by operational
status in real-time, organizes them by carrier/company group, and provides
an Excel workbook tab experience pinned at the bottom of the window.

--------------------------------------------------------------------------------
2. TECH STACK & TOOLS
--------------------------------------------------------------------------------
- Frontend: Vue 3 (Composition API with <script setup>)
- Build Tool & Dev Server: Vite 6 (ultra-fast HMR and building)
- Styling: Tailwind CSS 3 + PostCSS + Autoprefixer
- Icons: Native Unicode & SVG icons
- Backend API: Node.js + Express.js + CORS (REST API server in server/server.js)
- Runtime: Node.js v24 LTS + npm
- One-Click Launcher: start.bat (Windows batch script)
- GitHub Repository: https://github.com/nurillo-madaminov/CheckingBoard.git (branch: main)

3. DATABASE ARCHITECTURE & STORAGE (SUPABASE PLAN B IMPLEMENTED)
--------------------------------------------------------------------------------
Primary Cloud Database: Supabase (PostgreSQL with Realtime WebSockets)
SQL Migration & Seed File: supabase_schema.sql

A. SUPABASE TABLES:
1. public.companies:
   - id TEXT PRIMARY KEY (e.g., "comp-1")
   - name TEXT NOT NULL
   - note TEXT DEFAULT ''
   - order_index INTEGER DEFAULT 1
   - created_at TIMESTAMPTZ DEFAULT NOW()
   - updated_at TIMESTAMPTZ DEFAULT NOW()

2. public.drivers:
   - id TEXT PRIMARY KEY (e.g., "drv-1")
   - company_id TEXT NOT NULL REFERENCES companies(id) ON DELETE CASCADE
   - unit TEXT DEFAULT '' (e.g., "122", "898", "27092")
   - name TEXT NOT NULL (e.g., "MOUZ TEDLA", "JEAN JOACHIM")
   - sign TEXT DEFAULT 'SIGNED'
   - status TEXT DEFAULT 'READY'
   - notes TEXT DEFAULT ''
   - highlight_color TEXT DEFAULT ''
   - order_index INTEGER DEFAULT 1
   - created_at TIMESTAMPTZ DEFAULT NOW()
   - updated_at TIMESTAMPTZ DEFAULT NOW()

B. REALTIME WEBSOCKETS REPLICATION:
   - Enabled via: ALTER PUBLICATION supabase_realtime ADD TABLE companies, drivers;
   - Whenever any dispatcher changes a driver's status or moves lines, Supabase
     broadcasts the change live. All connected dispatchers receive the update
     instantly without refreshing their browser.

4. TABLE STRUCTURE & LOCKED COLUMNS
--------------------------------------------------------------------------------
The dynamic table consists of 5 fixed-width columns with zero jitter:
1. # (Order Number):
   - Fixed 56px width (Col 0).
   - Sequential Excel-style row number (1, 2, 3...) for both drivers and companies.
   - Acts as the ONLY drag handle (with grip indicator ⠿) for drag-and-drop reordering.
2. Driver (Unit - Name):
   - Fixed 320px width (Col 1).
   - Formatted as "[unit] - [driver name]" when unit is present, or "[driver name]".
   - Text selection is preserved. Clicking name selects the row without opening edit modal.
3. Sign:
   - Fixed 140px width (Col 2).
   - Dropdown with SIGNED / NO SIGN options.
4. Status:
   - Fixed 190px width (Col 3).
   - Operational statuses: AT PU, AT DEL, COVERED, GOING DEL, READY, SHOP, HOME, INACTIVE.
5. Notes:
   - Flexible remaining width (Col 4).
   - Inline text input with auto-save on blur / enter.

--------------------------------------------------------------------------------
5. COMPANY SEPARATOR ROWS & COLLAPSIBLE VIEWS
--------------------------------------------------------------------------------
- Order Number Handle (#): Companies have their own sequential order number cell
  on the left (Column 0, 56px) with drag grip (⠿ 1, ⠿ 2...). Companies can ONLY
  be dragged and reordered via this order handle.
- Closed / Collapsed by Default: When opening the app or switching views, companies
  start in a collapsed state by default for clean and structured browsing.
- Expand All / Collapse All Toggle: Added top bar button to quickly expand or collapse
  all companies in a single click.
- Main Tab vs Category Tabs Action Isolation:
  * In the main "CHECKING BOARD" tab: companies display action buttons (+ Add Driver,
    ✏️ Edit, 🗑️ Delete).
  * In all category tabs (AT PU/DEL, READY, etc.): all company action buttons are
    hidden to avoid accidental modifications outside the master view.

--------------------------------------------------------------------------------
6. DRAG AND DROP REORDERING SPECIFICATION
--------------------------------------------------------------------------------
1. Drivers:
   - Reordering is restricted STRICTLY to the order number (#) cell on the left.
   - Dragging cannot be triggered from driver name, dropdowns, notes, or buttons.
   - Prominent blue Excel-style insertion indicator (◀ --- ▶) dynamically shows
     whether the line will drop above or below the target row.
2. Companies:
   - Reordering is restricted STRICTLY to the company order number (#) cell on the left.
   - Full-width blue insertion guide line indicates target placement.
   - Reordering smoothly updates company order across state, storage, and Supabase.
3. Bottom Sheet Tabs:
   - The first tab (CHECKING BOARD) is fixed and locked in position 0.
   - All other tabs (tabs 1..N) can be reordered via drag-and-drop with vertical blue
     insertion line markers.
   - Custom tab order is persisted in localStorage ('checkingboard_tabs_order_v1').

8. DYNAMIC ROW AGING COLORS (WORKFLOW FRESHNESS SYSTEM)
--------------------------------------------------------------------------------
- Row background colors are dynamically calculated based on time elapsed since last check
  (lastCheckedAt timestamp), making dispatch workflow highly visible:
  * 0h (Newly checked): Fresh Green (rgb(220, 252, 231))
  * 1h - 2.5h: Aging Yellow (rgb(254, 249, 195))
  * 2.5h - 4h: Warning Orange (rgb(254, 215, 170))
  * 4h+ (or never checked): Overdue Red (rgb(254, 226, 226))
- Hover "✓" Quick Check Button: Dispatchers can click the "✓" button in the driver
  row hover actions to instantly refresh that driver line back to green.
- Modifying sign, status, or notes also automatically updates lastCheckedAt.
- Custom row highlight colors from the 🎨 palette take precedence if applied.
- Automatic Real-Time Aging Ticker: A 30-second reactive background timer runs
  continuously in `src/utils/freshness.js`. As time elapses (without needing page reloads
  or mouse clicks), every driver line actively shifts from Green → Yellow → Orange → Red.
- Added `last_checked_at TIMESTAMPTZ` column to `supabase_schema.sql` and synced in
  `supabaseService.js`.

--------------------------------------------------------------------------------
9. DAILY US EASTERN TIMEZONE SIGN RESET
--------------------------------------------------------------------------------
- Whenever the date changes in US Eastern Timezone (EST/EDT, America/New_York),
  all drivers' sign status automatically resets to 'NO SIGN'.
- Evaluated on initial page load, after Supabase data fetch, and via a periodic
  60-second background ticker to handle midnight rollover without reloading.

--------------------------------------------------------------------------------
10. RESET TO READY (RED) BUTTON & GLOBAL REAL-TIME SYNCHRONIZATION
--------------------------------------------------------------------------------
- The reset button in the top bar (next to Status Colors) resets all active drivers' status
  to 'READY' and clears `lastCheckedAt` to null.
- Global Real-Time Sync Across All Users: When any dispatcher clicks the reset button,
  it executes a PostgreSQL update on Supabase (`UPDATE drivers SET status = 'READY', last_checked_at = NULL WHERE status != 'INACTIVE'`)
  and sends a WebSockets Realtime broadcast (`fleet_reset`).
  All other active dispatchers automatically receive the event, re-fetch the fleet,
  update their rows to READY and Red simultaneously, and receive a toast alert:
  "Fleet reset to READY by another dispatcher".
- INACTIVE Drivers Excluded: Drivers with `status: 'INACTIVE'` are deliberately preserved
  as INACTIVE across the entire database. They remain strictly in the HOME/INACTIVE tab
  and do NOT get shown on the main CHECKING BOARD tab.
- This immediately marks all active driver rows in Red (Needs check ASAP / Overdue), giving
  dispatchers a synchronized clean slate for daily check rounds without altering inactive profiles.

11. NATIVE STATUS DROPDOWN & MULTI-OPEN BUG FIX
--------------------------------------------------------------------------------
- Reverted the custom status button/popup to a native HTML `<select>` element.
- Prevents multiple dropdown popups from lingering or opening simultaneously.
- When selected: displays only the concise status code (e.g., READY, COVERED, AT PU).
- While selecting: options show both code and description (e.g., "READY – Ready for Load").

--------------------------------------------------------------------------------
12. STATUS CHANGE FLOATING TOAST ALERTS & COLOR MATCHING
--------------------------------------------------------------------------------
- Positioned in the top-right corner of the screen (`top-3 right-3`).
- Dynamic Status Color Matching: The background, border, text, and checkmark circle of
  each alert dynamically match the status color being set:
  * AT PU / AT DEL: Soft yellow background (`#FEF08A` / `#FEF9C3`), amber border and text
  * GOING DEL: Soft blue background (`#DBEAFE`), blue border and text
  * READY: Soft green background (`#DCFCE7`), green border and text
  * COVERED: Soft amber background (`#FDE68A`), amber border and text
  * SHOP: Soft orange background (`#FFEDD5`), orange border and text
  * HOME: Soft red background (`#FEE2E2`), red border and text
- Prominent Transfer Location Display: The destination tab is displayed with maximum
  clarity inside a high-contrast bordered badge (e.g., `Transferred to: [ AT PU/DEL ]`),
  making it immediately obvious and easy to identify where the row has moved.
- Identical Fixed Size: Every alert card has the exact same dimensions (`320px` width
  by `64px` height, `w-80 h-16`) with clean text truncation, ensuring uniform geometry.
- No separate close `✕` icon; the entire alert card is clickable to dismiss immediately
  (plus 4-second auto-dismissal).
- Also triggers when new drivers are added to the fleet.

--------------------------------------------------------------------------------
13. INACTIVE DRIVERS FILTERING
--------------------------------------------------------------------------------
- Inactive drivers (status: 'INACTIVE') are automatically hidden from the master
  'CHECKING BOARD' tab.
- They remain viewable and manageable under the 'HOME/INACTIVE' tab.
